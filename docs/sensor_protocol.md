# PMW3360 传感器通信协议提取报告

对象:`fw_400_1000_1600.bin`(7252 B)/ `fw_400_4000_800.bin`(7284 B),主控 ATmega32U4(RAMEND=0x0AFF,2.5KB SRAM,与 32U4 完全吻合;SP=0x0AFF @0x117C-0x1182)。
本报告所有地址均为**字节地址**(反汇编清单中 JMP/RJMP 目标亦为字节地址)。
反汇编工具有两处系统性误码,本文已手工修正:

- `.word 0xFE07` = **SBRS r0, 7**(1111 1110 0000 0111;SPSR.bit7=SPIF),后跟 RJMP 构成 SPIF 忙等循环;
- `.word 0x959A/0x95EA/0x95FA/0x9483/0x9493/0x94FA` = **DEC r25 / DEC r30 / DEC r31 / INC r8 / INC r9 / DEC r15**(DEC=1001 010d dddd 1010)。

## 1. SPI 硬件层与事务原语(Q1)

### 1.1 硬件配置(两固件相同,位于 main=0x11B2 内)

| 地址 | 代码 | 含义 |
|---|---|---|
| 0x1220-0x1224 | `IN r24,DDRB; ORI r24,0x07; OUT DDRB,r24` | PB0/PB1/PB2 输出 |
| 0x1226 | `SBI DDRB,0` | PB0 冗余置输出 |
| 0x1228 | `SBI PORTB,0` | **NCS(PB0)=1**(空闲高) |
| 0x122A-0x122C | `LDI r24,0x5C; OUT SPCR,r24` | SPCR=0x5C=0101_1100:SPE\|MSTR\|CPOL=1\|CPHA=1\|SPR1 → **SPI mode 3**,f_SCK=fosc/64 |
| 0x122E-0x123A | 24 位倒计数延时 r18:r31:r30=0x02:0x70:0xFF=159,999×5 拍 | **50.0ms** 上电等待 |

- PB1=SCK、PB2=MOSI(硬件 SPI),PB3=MISO(复位默认输入,未改)。
- fosc=16MHz 由延时常数反推:160µs/35µs/180µs/20µs/50ms/10ms 全部与数据手册最小值**逐拍吻合**(见 §1.3);CLKPR=0x80/0x00 @0x11C8-0x11CC(div=1)。SPSR 从未写入 → SPI2X=0,**SCK=250kHz**。
- 不用 SPI 中断(SPIE=0),不用 SBIC/SBIS 直接测 SPSR。

### 1.2 事务原语(全部为内联展开的直线代码,无子程序)

**等待传输完成(每个字节后都有)**:
```asm
      OUT SPDR, rX
wait: IN   r0, SPSR        ; 0x2D
      SBRS r0, 7           ; SPIF
      RJMP wait
```
(例:0x1260-0x1266。)首字节后的延时用软件倒计数循环,不用硬件定时器。

**写寄存器** = 一个 NCS 窗口内发两字节:
```asm
CBI PORTB,0            ; NCS↓
LDI r25,<0x80|reg> ; OUT SPDR ; wait SPIF
<延时 180µs tSWW>(SBIW 循环 r31:r30=0x02CF=719×4 拍)
LDI r25,<data>     ; OUT SPDR ; wait SPIF
<延时 180µs>
SBI PORTB,0            ; NCS↑
```
(例:Power_Up_Reset 0x12A6-0x12C8;多笔写合并进同一 NCS 窗口时,每笔之间 180µs,见 §2 第 11/13 步。)

**单寄存器读** = 地址字节(MSB=0)→ tSRAD → 哑字节 → 取回:
```asm
CBI PORTB,0
LDI r25,<reg>      ; OUT SPDR ; wait SPIF
LDI r30,0x7F; LDI r31,0x02 ; SBIW/BRNE ×639   ; 639×4=2556 拍 = 159.75µs ≈ tSRAD(≥160µs)
OUT SPDR, r1           ; 哑字节(r1=AVR-GCC 清零寄存器,0x1178 EOR r1,r1); wait SPIF
IN   r25, SPDR         ; 数据
LDI r31,0x6A; DEC r31; BRNE ×106              ; 106+105×2=316 拍 = 19.75µs ≈ 20µs 读间隔
```
(例:0x12DC-0x1304 读 Motion。)

**NCS 翻转点全集**(fw1 `SBI/CBI 0x05,0` 的全部代码位置):0x1228/0x124E/0x125C/0x127E/0x1292/0x129C/0x12A6/0x12C8/0x12DC/0x1402/0x1410/0x1464/0x1472/0x154C/0x155A/0x157A/0x163A/0x168E —— **全部在初始化(0x1228-0x157A)和主循环 Motion_Burst(0x163A-0x168E)里,运行时没有任何对传感器的写事务**(fw2 相同,整体 +0x20)。

## 3. SROM 数据表(Q2 重点)

**位置:flash 0x00AC - 0x10A9,共 4094 字节,两份固件逐字节相同(已用 python 比对:True)。**

证据链:
1. 下载循环 `LDI r30,0xAC; LDI r31,0x00`(0x143C/0x143E)→ Z 指向 0x00AC;
2. 终点比较 `LDI r18,0xAA; LDI r19,0x10`(0x1440/0x1442)+ `CP r18,r30; CPC r19,r31`(0x1458/0x145A)→ Z==0x10AA 时结束 → 发送 0x00AC..0x10A9,= 0x10AA-0x00AC = **0x0FFE = 4094 字节**;
3. 熵扫描:0x0100-0x10FF 各 256B 块熵 7.10-7.35 bits/byte(数据特征),0x1100 起骤降至 6.6 以下(代码特征);SROM 区 256 种字节值全出现、最高频字节仅 29/4094(≈均匀分布)→ 编译过的传感器固件镜像;
4. 0x10AA 起字节变为低熵结构化数据(`00 01 00 00 60 11 12 00 02 00…`,〔推断〕USB 描述符等常量表),表尾边界干净;
5. 全固件 LPM 指令仅两处用途:0x144C(SROM 下载)与 0x1A2A-0x1B32(USB 描述符读取)→ SROM 只在开机下载一次,运行时无重载。

**与手册差异:数据手册要求 4096 字节,固件只发 4094 字节**(少 2 字节)。〔推断〕either 厂商 SROM 镜像就是 4094 字节,或循环终点常数(0x10AA)笔误少 2(0x10AC 才是 4096)——无法从镜像内部判定。

启动代码的 .data 拷贝(0x1184-0x1198)从 flash **0x1C52**(fw2:0x1C72)取 2 字节 `{0x01,0x00}` 写入 SRAM 0x0100-0x0101,.bss 清 1 字节 @0x0102(0x119A-0x11A8)。〔推断〕0x0100/0x0101/0x0102 即 USB 控制器寄存器 UDCON/UDIEN/UDINT 区(UDCON=0x01=DETACH,上电先摘下 USB)——注意反汇编工具把 0x0102 标成 UDIEN,与标准 32U4 映射(UDIEN=0x101)差一位,工具标签存疑。

## 4. Config1(0x8F)与 DPI 预设(Q3)

**写入点**:cmd 0x8F @0x14D0,data `OUT SPDR,r24` @0x14D8(两固件同一地址,该段代码逐字节相同);r24 的值在开机 0x1248 由 `LDI r24,imm` 决定,或由 PD0/PD1 引脚分流(0x17E8/0x17F0,fw2:0x1808/0x1810)。

| 固件 | 默认(0x1248) | PD0=0(0x17E8/fw2:0x1808) | PD1=0(0x17F0/fw2:0x1810) | Y+1 预设序号(默认/PD0/PD1) |
|---|---|---|---|---|
| fw_400_1000_1600 | **0x09 = 1000cpi** | 0x03 = 400cpi | 0x0F = 1600cpi | 1 / 2 / 3 |
| fw_400_4000_800 | **0x27 = 4000cpi**(字节 87 E2) | 0x03 = 400cpi | **0x0F = 1600cpi** | 1 / 2 / 3 |

(Config1 值=(cpi/100)-1,验证:0x03→400 ✓,0x09→1000 ✓,0x0F→1600 ✓,0x27→4000 ✓。)

**与文件名核对**:
- fw1 名义 {400,1000,1600} ↔ 实际 {400(PD0),1000(默认),1600(PD1)} —— **完全一致**;
- fw2 名义 {400,4000,800} ↔ 实际 {400(PD0),4000(默认),**1600(PD1)**} —— **第三档不符**:全镜像不存在 0x07(800cpi)的 Config1 值(`LDI r24,0x07` 在两份固件的代码区均无)。〔推断〕文件名错误,或厂商把 800 档固件误编成 1600(直接复用了 fw1 的 0x0F);"800" 亦无法用其他机制(如 USB 报告率)解释 Config1 层面的缺失。

**切换机制:没有运行时切换。**
- 两份固件的 SPDR 写访问与 NCS 翻转点全集都只落在初始化区 + 主循环突发读(io.txt 为**静态全量清单**,循环体只出现一次,已逐条核对;fw2 同样如此);
- 全镜像没有任何从主循环跳回初始化区的转移(唯一进入 0x124E 的跳转来自开机 strap 块 0x17EE/0x17F6);
- 三档 DPI 是编译期定死的三选一:**上电时采样 PD0/PD1**(这两脚同时是运行时按钮输入,内部上拉、低有效——0x11D2 PORTD|=0x3F,主循环 0x16AA 起扫 PIND0-5):按住 PD0 对应键上电 → 400;按住 PD1 对应键 → 第三档;都不按 → 默认档(中位值)。
- 开机选中的 Y+1 预设序号只在 0x1754-0x1762(fw2:0x1774-0x1782)被读一次,映射成 LED 呼吸模式 r17=2/3/5(0x18C6/0x18B2/0x190C 分支),让用户**靠灯效辨认当前档位**;此后不再影响传感器。
- 运行时按键全部走 USB 按键事件(Y+10 事件位,去抖 32 帧×62.5µs=2ms,阈值判断如 0x16CC `CPI r25,0x20`),最终打包进 USB 报告(0x1792-0x17BC 经 r2-r7 环形累加器写端点缓冲 0x00E8-0x00F1),**不回写传感器**。

## 5. Lift_Config(Q4)

cmd 0xE3 @0x14EE,data **0x02** @0x14F8(两固件相同;fw2 同址,因 <0x154B)。
0x02 = LIFC[1:0]=0b10 → **标称抬离高度 +2mm**(数据手册默认档)——与产品名 "2mm" 一致。✓

## 6. Angle_Snap(Q6)

cmd 0xC2 @0x155E,data **r1=0x00** @0x1566(fw2:cmd @0x157E,data @0x1586)。
**写入了,但值 0x00 → AS_EN(bit7)=0,即 Angle Snap 关闭**。r1 是 GCC 零寄存器(0x1178 `EOR r1,r1` 清零,其后无写 r1 指令),数据字节确为 0x00。两份固件相同。

## 7. 运行时位移读取(Q5)

**方式:Motion_Burst(0x50)事务,但只读出 4 个增量字节,不是完整 12 字节;在主循环中调用,不在中断里。**

fw1 主循环结构:
- 节拍:Timer0 CTC,TCCR0A=0x02/TCCR0B=0x02(clk/8)/OCR0A=0x7C(0x1596-0x159E)→ 62.5µs;每圈开头忙等 TIFR0.TOVD(SBIS 0x15,1 / SBI 清除,0x15E6-0x15EA)→ **主循环周期 62.5µs(16kHz)**;
- LED 状态机(r17=2/3/5,r8/r9 计数器与 0x0F/0x10 比较,控制 PB5/PB6/PD7,0x15EC-0x1638);
- **突发读 0x163A-0x168E**(fw2:0x165A-0x16AE):

```asm
163A  CBI PORTB,0            ; NCS↓
163C  LDI r25,0x50 ; OUT SPDR ; wait SPIF     ; 地址 0x50(MSB=0)
1646  LDI r30,0xBA ; DEC/BRNE ×186              ; 34.75µs ≈ tSRAD(burst ≥35µs)
164E  OUT SPDR,r1 ; wait          ; 哑字节1 → 时钟入 frame[0] Motion(丢弃)
1656  OUT SPDR,r1 ; wait          ; 哑字节2 → frame[1] Observation(丢弃)
165E  OUT SPDR,r1 ; wait          ; 哑字节3 → frame[2] Delta_X_L 移入 SPDR
1666  IN r24,SPDR ; MOV r12,r24   ; X_L
166A  OUT SPDR,r1 ; wait
1672  IN r24,SPDR ; MOV r13,r24   ; X_H
1676  OUT SPDR,r1 ; wait
167E  IN r24,SPDR ; MOV r10,r24   ; Y_L
1682  OUT SPDR,r1 ; wait
168A  IN r24,SPDR ; MOV r11,r24   ; Y_H
168E  SBI PORTB,0                 ; NCS↑
```

即主发 7 字节(地址+6 哑字节),取回突发帧 **frame[2..5] = Delta_X_L/H、Delta_Y_L/H**;Motion、Observation 位被时钟移过但从不检查(MOT 位不判断,直接按 16kHz 采增量)。SQUAL/像素/快门等后 6 字节不读。
- 寄存器用途由累加代码确证:0x1792 `ADD r24,r12; ADC r25,r13` = X 累加,0x179A `ADD r18,r10; ADC r19,r11` = Y 累加 → r12/r13=X 低/高,r10/r11=Y 低/高 ✓ 与 3 哑字节对齐推断自洽。
- **主循环上下文**:0x163A 由 0x1634(`CP r8,r24; BRCS`)或 0x17F8(`SBI PORTD,7; RJMP 0x163A`)进入,均为主循环直线流。整个固件只挂了两个中断向量:0x0028→0x194A、0x002C→0x198C(fw2:0x196A/0x19AC),两个 ISR 内只有 USB 寄存器/端点缓冲访问(0x197C 写 UDINT 区、0x19B0+ 端点 FIFO 0x00E8-0x00EE),**无任何 SPDR/PORTB0 访问**(io.txt 全量核对)→ SPI 完全不在中断上下文。
- 位移不直接发送,先 16 位累加(r2-r7 环形变量,0x177C-0x17BC),有按键变化或增量非零才组 USB 报告(0x1792-0x17BC:按钮字节、X_L、X_H、Y_L、Y_H 顺序写端点缓冲 0x00F1)。

## 8. 两固件差异的完整机制(供参考)

逐字节 diff:0x0000-0x118A 完全相同(除向量表两处)、SROM 区 0x00AC-0x10A9 完全相同。差异 =
1. 0x002A/0x002E:两个已挂接向量的目标地址 +0x20(0x194A→0x196A,0x198C→0x19AC);
2. 0x118B:`LDI r30,0x52→0x72` —— .data 源地址随镜像尾移 +0x20(0x1C52→0x1C72,内容同为 {0x01,0x00});
3. 0x11AC:`RJMP 0x1C4E→0x1C6E` —— main 返回地址 +0x20;
4. 0x1242/0x1246:strap RJMP 目标 +0x20(0x17E8/0x17F0→0x1808/0x1810);
5. **0x1248-0x1249:`LDI r24,0x09→0x27` —— 开机默认 Config1(1000→4000cpi)**;
6. **fw2 在 post-SROM 配置窗口插入一笔 `0x07←0x40`(cmd 0x87@0x154C,data 0x40@0x1556),恰 +32 字节**,其后全部代码平移 +0x20(同地址字节因此大量"不同")。

即:fw2 = fw1 骨架 + 默认 DPI 改 4000 + 一笔额外的未公开寄存器写。〔推断〕该笔 0x87/0x40 写与 4000-DPI SKU 相关(0x87 按写命令约定=寄存器 0x07,手册参考卡中 0x07 是只读的 SQUAL,故此解读存疑,也可能 vendor 私有映射)。

## 9. 未实锤点汇总(全部标"推断")

1. **寄存器 0x3B←0xB6**(0x1260/0x126A,上电复位之前):参考卡无此寄存器,用途不明(疑为厂商 SPI 校准/私有初始化步骤)。
2. **NCS 40µs↓/40µs↑ 无数据脉冲**(0x1292-0x12A4):目的不明(唤醒/接口复位脉冲?)。
3. **0x3B 写与 Power_Up_Reset 之间的 299.2ms 延时**(0x1280-0x1290):手册无此要求,目的不明。
4. **未公开寄存器写**:0x0D←0x00、0x11←0x00(0x1494/0x14B0)、0x2B←0x10、0x2C←0x0A(0x150E/0x152C)两固件都有;fw2 独有 0x07←0x40。语义全部未知;其中 "0x87=写 0x07" 依赖写命令约定,而 0x07 在公开手册里是只读 SQUAL,可能实为厂商私有寄存器映射。
5. **SROM 只发 4094 字节**(0x00AC-0x10A9),手册要求 4096:差 2 字节,是镜像本来就这么长还是循环终点常数笔误,无法从镜像内部判定。
6. **无任何传感器自检**:不读 Product_ID(0x00,应=0x42)、不读 SROM_ID(0x2A)、不轮询 Observation;下载成败不可知。
7. **fw2 第三档 DPI 与文件名不符**:代码实为 1600cpi(0x0F),文件名写 800;0x07 在 fw2 全镜像不存在。
8. **突发帧对齐**:首个 IN 取 frame[2]=Delta_X_L 的结论基于"3 个哑字节+累加器配对(r12/r13=X,r10/r11=Y)"双重佐证,但固件从不读 Motion/Observation 字节做交叉验证。
9. **主循环周期 62.5µs(16kHz)是代码意图**;USB 实际上报率由"有变化才发"逻辑决定,固件里看不到最终轮询率(端点描述符 bInterval 在数据区,未逐一解析)。
10. **.data 两字节 {0x01,0x00}→SRAM 0x100-0x101** 解读为 UDCON/UDIEN 初始值(DETACH);反汇编工具对 0x0102 的寄存器名(UDIEN)与标准 32U4 映射(UDINT)差一位,工具标签存疑。
11. **向量表跨度**:已挂接的 0x0028/0x002C 按 32U4 标准向量序为 Timer1_COMPB/Timer1_OVF(处理内容却是 USB 相关);镜像向量表区一直延伸到 0x00AB(43 槽),多于本人所记 32U4 向量数——0x005C-0x00AB 可能是厂商用 `JMP 0x11AE` 填的填充区,也可能该芯片向量更多,未实锤(不影响传感器结论:两 ISR 均无 SPI 访问)。
12. **16MHz 时钟**:由延时常数与手册最小值逐拍吻合反推(四个独立常数精确命中);晶振/时钟源为熔丝配置,镜像内不可见。PB5/PB6 被用作 LED 输出(0x11E6 DDRB|=0x60),说明用的是专用 XTAL 引脚而非 PB5/6(那是 ATmega328P 的布局),与 32U4 一致。

## 10. QMK 移植要点(直接可用的结论)

- SPI:mode 3,≤250kHz,NCS 空闲高;写=cmd(0x80|reg)+data,笔间≥180µs;读=addr→≥160µs(burst ≥35µs)→哑字节→取回,读后≥20µs。
- 初始化可直接照抄 §2 的 17 步(含全部未公开寄存器写,保守起见原样保留);SROM 用 4094 或补齐 4096 需实测。
- 默认参数:Config2=0x00、Lift_Config=0x02(+2mm)、Angle_Snap 关、DPI 由编译期预设+开机 strap 选择(移植 QMK 时可改为运行时写 0x8F 循环切档,协议层无障碍——只是原固件没这么做)。
- 运行时读:Motion_Burst 0x50,仅需 Delta 四字节;固件不检查 MOT 位,直接累加。
