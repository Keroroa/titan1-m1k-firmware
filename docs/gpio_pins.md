# GPIO 引脚分配报告(滚轮编码器 / 按键 / LED / 备用脚)

对象:`fw_400_1000_1600.bin` / `fw_400_4000_800.bin`(主控 ATmega32U4 QFN44,16MHz)。
本文是《PMW3360 传感器通信协议提取报告》(`sensor_protocol.md`)的姊妹篇,负责 GPIO 层;
所有地址为**字节地址**。除特别注明,两份固件 GPIO 相关代码逐字节相同(fw2 在 0x154C 插入一笔
传感器寄存器写后整体 +0x20,GPIO 逻辑不变;init 块 0x11D0-0x1230 已用 python 比对:`True`)。

**方法学说明(重要,避免被 io.txt 误导)**:
`fw_400_1000_1600.io.txt` 中 0x00B6-0x1000 的全部条目(PIND/PINC/PINB/PINF/PORTF/PORTC 等访问,
含 0x0BF6/0x0E66/0x0EA0 的 PINB、0x07AA 的 PINF、0x0CAE/0x0CD2/0x0DEE 的 PORTF、0x0B4E 的 PORTC)
落在 **SROM 数据区 0x00AC-0x10A9** 内,是对数据字节的误解码,**全部无效**。
真实代码区 = 0x10AA-0x1C54。本文所有结论只基于真实代码区,并用修正版解码器
(`_re_decode.py` 仍把部分 SBRS/SBRC 误判为 `.word`,因其掩码要求 bit3=1;AVR 实际编码 bit3=0。
本文用临时脚本按 `word = 0xFC00/0xFE00 | r<<4 | b` 手工修正后全量重解码 0x10AA-0x1C54)。

另外核实:真实代码区对 GPIO(SRAM 0x0020-0x003F)只有 IN/OUT/SBI/CBI/SBIC/SBIS 访问,
**没有任何 LDS/STS 打到 GPIO 寄存器**;向量区(0x10AA-0x1178)与两个 USB ISR(0x194A/0x198C 起)
内也无任何 GPIO 访问。

## 1. 初始化全序列的端口方向/上拉掩码(0x1178-0x1240)

复位后所有 DDR/PORT = 0x00,逐条过 init:

| 地址 | 指令(修正后) | 效果 |
|---|---|---|
| 0x11D0-0x11D4 | `IN r24,PORTD(0x0B); ORI 0x3F; OUT` | **PORTD \|= 0x3F** → PD0-PD5 内部上拉 |
| 0x11D6-0x11DA | `IN r24,DDRC(0x07); ANDI 0x3F; OUT` | **DDRC &= 0x3F** → PC6/PC7 保持输入(其余位无变化) |
| 0x11DC-0x11E0 | `IN r24,PORTC(0x08); ORI 0xC0; OUT` | **PORTC \|= 0xC0** → PC6/PC7 内部上拉 |
| 0x11E2 | `SBI DDRD(0x0A),6` | PD6 → **输出** |
| 0x11E4-0x11E8 | `IN r24,DDRB(0x04); ORI 0x60; OUT` | **DDRB \|= 0x60** → PB5/PB6 输出 |
| 0x11EA | `SBI DDRD,7` | PD7 → **输出** |
| 0x11EC | `SBI PORTB(0x05),5` | PB5 = 1 |
| 0x11EE | `SBI PORTB,6` | PB6 = 1 |
| 0x11F0 | `SBI PORTD(0x0B),7` | PD7 = 1 |
| 0x1218-0x121C | `SBIC PIND(0x09),2 → 否则 JMP 0x7E00` | **PD2 strap**:PD2=0 进 bootloader |
| 0x1220-0x1224 | `IN r24,DDRB; ORI 0x07; OUT` | **DDRB \|= 0x07** → PB0/PB1/PB2 输出 |
| 0x1226 | `SBI DDRB,0` | PB0 冗余置输出 |
| 0x1228 | `SBI PORTB,0` | PB0(NCS)= 1(空闲高) |

运行时唯一的额外方向/上拉改动:**无**(运行时只翻转已配置为输出的位)。

## 2. 滚轮编码器:**PC6 + PC7**(QFN44 引脚 31/32),半正交解码

证据链(全部实锤):

**输入配置**:DDRC &= 0x3F、PORTC |= 0xC0(0x11D8/0x11DE)→ PC6/PC7 = 输入 + 内部上拉。
全固件对 PINC(0x06) 的真实读取只有两处,都在主循环(0x1690/0x1698);init 之外无其它消费者。

**读取与解码(0x1690-0x16A8,每帧一次)**:
```asm
1690: IN   r24, PINC        ; 读 PINC
1692: BST  r24, 6           ; T = PC6
1694: EOR  r24, r24
1696: BLD  r24, 0           ; r24 = PC6(A 相)
1698: IN   r25, PINC        ; 再读 PINC
169A: ADC  r25, r25         ; 左旋进位:C = PINC.bit7 = PC7(B 相)
169C: EOR  r25, r25
169E: ADC  r25, r25         ; r25 = PC7
16A0: CP   r24, r25         ; A == B ?
16A2: BRNE 0x16A6
16A4: RJMP 0x1856           ; A==B(整拍/卡位态)→ 计数判定
16A6: STD  Y+8, r24         ; A!=B(半拍中间态)→ 记住此刻 PC6
16A8: MOV  r15, r1          ; 本帧无滚轮事件(r15=0)
```
(0x169A 的 `ADC r25,r25` 是标准的"取 bit7 进 C"惯用法:C_out = PINC.bit7,与进入时的 C 无关。)

**计数判定(0x1856-0x186A,A==B 帧进入)**:
```asm
1856: LDD  r31, Y+9         ; 上一次计数时的 PC6(整拍相位)
1858: MOV  r15, r1
185A: CP   r24, r31         ; 整拍相位没变 → 没滚动
185C: BRNE 0x1860
185E: RJMP 0x16AA
1860: LDD  r15, Y+8         ; 中间态的 PC6
1862: EOR  r15, r24         ; 与新整拍相位异或
1864: ADD  r15, r15         ; ×2 → 0 或 2
1866: DEC  r15              ; 0→0xFF(-1),2→1(+1)   ← 0x94FA=DEC r15
1868: STD  Y+9, r24         ; 记录新整拍相位
186A: RJMP 0x16AA
```
Y+8/Y+9 在主循环入口清零(0x15B0/0x15B2,上电假定 A=B=0)。

**解码语义**(实锤,方向↔物理转向取决于板上 A/B 接线,标推断):
- 编码器两相 = PC6/PC7,整拍(卡位)态为 A==B;
- 经半拍态(A≠B)→ 新整拍态(A==B 且 PC6 变化)计 **±1 / 格**:
  `方向 = 中间态PC6 XOR 新整拍PC6` → 异或=1 → **+1**,异或=0 → **-1**(0xFF);
- r15 即滚轮增量,作为 USB 报告第 6 字节(见 §3);端点忙时的重发路径会累加
  (0x18AC `ADD r15,r3`,r3 为上次保存值 0x17C6);
- 报告发送条件包含 `r15 != 0`(0x187C `AND r15,r15; BRNE`)→ 滚一格必发一帧;
- 弱点(推断):两相变化都落在同一 62.5µs 帧内(极快滚动)时,Y+8 是陈旧值,方向可能判反;
  每格只计 1 次(4 态只用 2 个整拍态)。

**结论:滚轮编码器在 PC6/PC7,不在 PD 口、不在 PB/PF。** io.txt 里那些"PINB/PINF"读取全是 SROM 数据区的假指令。

## 3. 按键:PD0-PD5 扫描,PD0-PD4 → USB 报告 bit0-4,PD5 扫描但被 0x1F 掩码丢弃

### 3.1 扫描与去抖(0x16AA-0x1752,每帧一次)

```asm
16AA: IN   r25, PIND        ; 读 PIND
16AC: IN   r24, EIFR(0x1C)
16AE: COM  r24
16B0: ORI  r24, 0x30
16B2: AND  r24, r25         ; r24 = PIND & (~EIFR | 0x30)
16B4: LDI  r18, 0x0F
16B6: OUT  EIFR, r18        ; 清 INT0-3 边沿标志
```
`~EIFR|0x30` 的作用(实锤):EICRA=0x55(0x11F4)= INT0-3 **任意逻辑变化**触发,EIMSK=0 不开中断,
但边沿仍会置 EIFR 标志 → PD0-PD3 只要本帧内出现过任何边沿,该位就被强制当"按下"(0)处理,
即**帧间边沿锁存**,对抗 62.5µs 采样窗内的抖动/快按快放;PD4/PD5(0x30 直通)无此辅助。

之后 6 个按键结构相同(位 i:PD i,累计器 Y+5/Y+7/Y+2/Y+6/Y+3/Y+4):
- 按下(当前为 0):报告位置 1,累计器清零(0x183A/0x182A/0x181A/0x180A/0x17FC 各 fall-through,`OR (~PIND)&bit`);
- 释放后锁存:上一帧报告为 1 且当前已松开 → 累计器++(0x16DC 型),**累计器 <0x20(32 帧 ≈2ms)期间报告位继续保持 1**(0x16E6 型 `ORI`),到 32 帧才放掉 —— 即"按下立即生效、松开延时 32 帧"的单边去抖;
- bit0(PD0)特殊:每帧先对 Y+10 做**整字节赋值**(0x184A `STD Y+10, (~PIND)&1` 或 0x16CA/0x16D0 的 0x01/0x00),其 32 帧释放锁存走同一模式(0x16C2-0x16D0);bit0 同时充当每帧 Y+10 的"清底"。

### 3.2 位映射(实锤)

| 按键 | 报告位 | 代码证据 |
|---|---|---|
| PD0 | bit0(0x01) | 0x184A-0x1852(整字节赋值含 bit0) |
| PD1 | bit1(0x02) | 0x16E8 `ORI r25,0x02` |
| PD2 | bit2(0x04) | 0x1702 `ORI r19,0x04` |
| PD3 | bit3(0x08) | 0x171C `ORI r19,0x08` |
| PD4 | bit4(0x10) | 0x1736 `ORI r19,0x10` |
| PD5 | bit5(0x20) | 0x1750 `ORI r19,0x20` —— **但被丢弃,见下** |

报告发送前(0x176E-0x1776):
```asm
176E: LDD  r20, Y+10
1770: ANDI r20, 0x1F        ; ← 只保留 bit0-4!
1772: LDD  r31, Y+11
1774: ANDI r31, 0x1F
1776: CP   r31, r20         ; 与上次发送值比较,不同才发
```
发送字节 = `Y+10 & 0x1F`(0x17A8 `STS 0x00F1, r20`)→ **PD5 的 bit5 永远进不了 USB 报告**,
且比较也用掩码值 → PD5 变化不触发发送。与 HID 报告描述符完全吻合(flash 0x111B-0x115F):
`05 09 19 01 29 05`(Usage Page Button, Usage Min 1 / **Max 5**)、`95 05`(Report Count 5)
→ **产品就是 5 按键**(bit5 是 3 位填充的一部分)。PD5 = 固件扫描了但"断线"的第 6 个键位
(〔推断〕同板更高配 SKU 留位/测试点,或彻底弃用)。

报告 6 字节布局(0x17A8-0x17BC 依次写端点 FIFO 0x00F1,实锤;与描述符一致):
```
[0]=按钮(5bit+3pad) [1]=X_L [2]=X_H [3]=Y_L [4]=Y_H [5]=滚轮(r15,±1/格)
```

### 3.3 上电 strap(PD0/PD1/PD2,实锤;键名对应标推断)

| 地址 | 判定 | 效果 |
|---|---|---|
| 0x1218-0x121C | PD2=0 | `JMP 0x7E00` 进 bootloader |
| 0x1240-0x1242 | PD0=0 | Config1=0x03(400cpi),Y+1=2(预设 2)→ 0x17E8-0x17EE |
| 0x1244-0x1246 | PD1=0 | Config1=0x0F(1600cpi),Y+1=3(预设 3)→ 0x17F0-0x17F6 |
| 0x1248-0x124C | 都不按 | Config1=0x09(1000cpi,fw2=0x27 即 4000cpi),Y+1=1(预设 1) |

按住"键"上电选 DPI 档:PD0(报告 bit0=左键〔推断〕)→ 400;PD1(bit1=右键〔推断〕)→ 第三档;
PD2(bit2=中键〔推断〕)→ bootloader(中键上电进 boot 是常见 OEM 设计)。
Y+1 无任何运行时写入者(全镜像仅 0x124C/0x17EC/0x17F4 三处 STD Y+1)→ **无运行时 DPI 切换**,
与传感器报告结论一致。

## 4. PE / PF / PB4 / PB7:全部未使用(实锤)

- **PF 口**(PINF 0x0F / DDRF 0x10 / PORTF 0x11,即 I/O 空间 0x0F/0x10/0x11):真实代码区 0 访问。
  io.txt 中 0x07AA(IN PINF)、0x0CAE/0x0CD2/0x0DEE(PORTF PF4 置 1/PF5 清 0)全在 SROM 数据区,无效。
  PF0-PF7 处于复位态:输入、无上拉、悬空(模拟输入脚)。
- **PE 口**(0x0C/0x0D/0x0E):真实代码区 0 访问。PE2(/HWB,引脚 33)、PE6(INT6,引脚 1)未用;
  EIMSK=0(0x11F8 `OUT 0x1D, r1`)→ INT6 也未开。
- **PB4**(引脚 28):输入、无上拉、从未读/写(io.txt 的 `SBIC PINB,4` @0x04AE/0x0EA0 是数据区垃圾)。
- **PB7**(引脚 12):输入、无上拉、从未访问。
  ※ ATmega32U4 的 XTAL1/XTAL2 是**专用引脚 17/16**(数据手册 QFN44 引脚序:PB7(12)-RESET(13)-VCC(14)-GND(15)-XTAL2(16)-XTAL1(17)-PD0(18)...),
  **不与 PB6/PB7 复用** —— PB5/PB6 当 LED 用不影响晶振,传感器报告 §9.12 的推断成立,16MHz 结论无需修正。
- PB3(引脚 11):输入、无上拉,由硬件 SPI 用作 MISO(复位默认即输入,固件未再配置)。

## 5. LED:PB5 / PB6 / PD7(实锤为引脚行为;电气极性未知,标推断)

三个输出(PB5 引脚 29、PB6 引脚 30、PD7 引脚 27),init 全部置高(0x11EC/0x11EE/0x11F0)。
状态机在每帧开头(0x15EC-0x1638),r17 = LED 模式,每帧由 DPI 预设重载(0x1754-0x1762):
**Y+1=1(默认档)→ r17=2;Y+1=2(PD0 strap)→ r17=3;Y+1=3(PD1 strap)→ r17=5**。
(r17=4 的分支 0x15FE 存在但不可达,死代码。)

计数器:r9(0x1606 `DEC r9`,模式 3 在 0x18B8 额外多减一次 → 相位 2 倍速)、r8(0x1624 `DEC r8`),
减到 0x10 归 0(0x160A-0x160E / 0x1628-0x162C),周期 256 帧。三个输出每帧行为:

| 模式(档位) | PB5 | PB6 | PD7 | 证据 |
|---|---|---|---|---|
| 2(预设1,默认) | 每 256 帧:239 帧高、17 帧低(r18=0x0F/r25=0x10) | 每帧无条件置高(0x161C),init 后**永不清除** | 每帧置高(0x1622 r17==0 → 0x17F8),**常高** | 0x18C6-0x18CE, 0x161A-0x1622 |
| 3(预设2,400cpi) | 同上,但 r9 双倍速 → 低窗每 128 帧 | 同上(常高) | 256 帧中仅 r8∈[0..3] 的 4-5 帧为低,约 98% 高 | 0x18B2-0x18C4, 0x162E-0x1638 |
| 5(预设3,1600cpi) | 每 256 帧:248 帧高、8 帧低(r18=0x06/r25=0x07) | 常高 | **每帧被清低**(r17=0x0F 恒 ≥ r8),且 r8 永远 <r24=0x10 → 置高分支(0x1638)不可达,**常低** | 0x190C-0x1914, 0x162E-0x1638 |

即:**PB6 = 从 init 起常高**(全固件无 `CBI PORTB,6`);**PB5 = 固定占空比的周期性窄低脉冲**
(非渐变呼吸:无任何斜率/渐亮计数器,窗宽固定);**PD7 = 档位相关:档 1/2 几乎常高,档 3 常低**
(另有 0x11F0/0x17F8 置高、0x18EC 清低)。

〔推断〕LED 亮灭的电气极性(高有效还是低有效)无原理图不可知 → 视觉效果二选一:
高有效则"档 3 熄灭 PD7、其余基本全亮";低有效则"档 3 点亮 PD7、PB5 呈周期窄闪"。
传感器报告所说"呼吸模式"经逐帧复核**不成立**:它是固定占空/固定周期的脉宽图案,不是强度渐变。

## 7. 未实锤点汇总

1. **按键物理名称**(左/右/中/后退/前进):bit→HID Usage 1-5 的映射是实锤(描述符 0x1121-0x112F),
   "usage 1=左键"等依赖 USB 惯例;strap 佐证(PD2 上电进 boot ≈ 中键、PD0/PD1 ≈ 左/右键选 DPI)是推断。
2. **PD5 的真实用途**:固件只证明"扫描+去抖+bit5 计算后丢弃"。是 SKU 留位、测试点还是飞线按键,不可知。
3. **PD6 输出恒低的用途**:固件无任何翻转/读取。不能排除是某个芯片的使能脚/模式脚或第二颗 LED(常亮或常灭取决于极性)。
4. **LED 电气极性**(高/低有效)与外观效果:引脚行为 100% 实锤,亮灭语义标推断。
   传感器报告的"呼吸模式"应修正为"固定占空周期脉冲;PD7 才是档位差异位(档3 常低,档1/2 近常高)"。
5. **滚轮方向符号 ↔ 物理滚动方向**:解码逻辑实锤(+1/-1 产生条件见 §2),但 +1 是"上滚"还是"下滚"取决于板上 A/B 相接线,镜像内不可见。
6. **极快滚动时的方向误判窗口**:一个帧(62.5µs)内跨过完整正交周期时,Y+8 为陈旧中间态,方向可能算反 —— 这是半正交解码的固有弱点,实际是否发生取决于用户滚动速度(推断)。
7. **主循环节拍对 LED 周期的缩放**:Timer0 明确配置为 62.5µs/帧(OCR0A=0x7C,0x1596-0x159E),但每帧在 0x1764-0x176A 还会(开中断)轮询一个 USB 寄存器区变量(0x1944 读 SRAM 0x0102)直到非零 —— 若该等待被 USB 事件节流(如 SOF),实际帧周期会拉长,LED 周期(本文按 256 帧=16ms 计算)按比例变化。该寄存器区归属属传感器报告已标注的"工具标签存疑"范围,不影响任何引脚结论。
8. **PF0-PF7/PB4/PB7/PE 在板上的实际接线**:固件侧 100% 未使用,但板上可能接了固件不碰的东西(不可知)。

## 8. 对 QMK 移植的直接结论

- 矩阵极简:6 输入键(PD0-5,上拉、低有效,其中 PD5 本固件弃用)+ 2 编码器相(PC6/PC7,上拉)+ 3 LED(PB5/PB6/PD7)+ NCS(PB0)+ 硬件 SPI(PB1/PB2/PB3)。无 PE/PF/PB4/PB7 占用,全部空闲可用。
- 编码器是**半正交(每格 1 计数)**,QMK 用标准 `ENCODER` 全正交会每格计 2,需按每格 1 分频或改用自定义解码;方向符号按 §2 校准。
- 按键去抖:按下即时、释放 32 帧(≈2ms)锁存;PD0-3 另有帧间边沿锁存(EICRA 任意变化采样)。QMK 直接用 2ms 以上对称去抖即可覆盖。
- strap(PD0/PD1 选档、PD2 进 boot)在 QMK 下可重实现为"按住上电"的组合,或改为运行时写 Config1(0x8F)切档(协议层无障碍,见传感器报告 §10)。
